# 소형 모델 기반 근거 추출 조사

- 상태: 조사 문서, 도입 결정 아님
- 작성일: 2026-09-17
- 실행 조건: CPU 8~12코어 우선

## 결론

소형 모델은 문서의 진실 여부를 판정하면 안 된다.
검색 전에 검증 가능한 근거 신호를 추출하는 보조기로만 검토한다.

첫 구현 후보는 아니다.
원천 메타데이터, 구조 보존 청킹, 최신성 순위를 먼저 평가한다.
그 방식으로 잡히지 않는 충돌이 남을 때만 소형 모델을 시험한다.

시험 순서는 다음과 같다.

1. 정규식과 원천 메타데이터 기준선
2. Qwen2.5-3B-Instruct 양자화 모델
3. NuExtract 2.0 2B 비교 모델

모델이 기준선보다 측정 가능한 이득을 내지 못하면 도입하지 않는다.

## 추출 대상

모델은 문서에서 다음 구조만 추출한다.

- 주장 주제 또는 키
- 값이나 목록
- 적용 범위와 조건
- 시행일과 만료일
- 폐기, 대체, 승인 표현
- 대체 문서 URL
- 원문 근거 구간과 문자 위치
- 모델 버전과 원문 내용 해시

예시는 다음과 같다.

```json
{
  "claimKey": "supported_event_types",
  "values": ["CREATED", "UPDATED", "DELETED"],
  "scope": "production",
  "effectiveAt": null,
  "status": "active",
  "replacementUrl": null,
  "evidence": {
    "text": "현재 이벤트 타입은 CREATED, UPDATED, DELETED다.",
    "start": 120,
    "end": 157
  }
}
```

이 결과는 충돌 후보를 찾거나 검색 메타데이터를 보강하는 데만 쓴다.
원문을 대신하지 않는다.

## 안전 조건

- 추출 결과로 문서를 삭제하거나 검색에서 제외하지 않는다.
- 모든 값은 제시한 원문 구간에서 다시 확인한다.
- 원문과 일치하지 않는 결과는 저장하지 않는다.
- 원문 텍스트를 최종 근거로 유지한다.
- 변경된 문서만 비동기로 처리한다.
- 내용 해시가 같으면 기존 결과를 재사용한다.
- 모델 이름, 버전, 프롬프트 버전을 함께 저장한다.
- 낮은 확신 점수만으로 진실과 거짓을 나누지 않는다.

문자 위치 검증은 일반 코드로 수행한다.
모델에게 자기 출력을 검증하게 하지 않는다.

## 후보 모델

### Qwen2.5-3B-Instruct

공식 모델 설명은 한국어를 포함한 다국어 지원과 JSON 출력을 명시한다.
일반 지시 모델이라 추출 형식을 프롬프트로 정의해야 한다.

장점:

- 한국어 지원이 명시되어 있다.
- JSON 구조 출력에 맞춘 개선이 있다.
- 3B 크기로 CPU 양자화 시험이 가능하다.

주의점:

- 정보 추출 전용 모델이 아니다.
- 원문에 없는 값을 생성할 수 있다.
- 실제 CPU 처리량과 메모리는 대상 장비에서 측정해야 한다.

권장 역할은 첫 범용 모델 기준선이다.

### NuExtract 2.0 2B

구조화 추출을 목적으로 만든 2B 모델이다.
JSON 템플릿에 맞춰 값을 채우는 방식이 핵심이다.

장점:

- 추출 작업과 출력 형식이 제품 목적에 가깝다.
- 다국어와 긴 문맥을 목표로 한다.
- 범용 대화 능력보다 구조 추출에 집중한다.

주의점:

- 한국어 정확도는 별도 평가가 필요하다.
- 시각 입력도 다루는 모델이라 텍스트 전용 운영에는 부담일 수 있다.
- 배포 형식과 CPU 추론 도구 호환성을 확인해야 한다.

권장 역할은 Qwen 기준선의 비교 모델이다.

### NuExtract-tiny 0.5B

매우 작은 추출 전용 기준선으로만 본다.
공식 자료에서 한국어 성능은 확인되지 않는다.
새 서비스의 기본 후보로 바로 선택하지 않는다.

### Gemma 3 4B IT

공식 설명은 140개 이상 언어 지원을 명시한다.
3B 모델보다 무거운 범용 비교 후보로 사용할 수 있다.

CPU 비용이 더 클 수 있다.
라이선스 조건과 배포 요구도 함께 확인해야 한다.
앞의 두 후보가 부족할 때만 시험한다.

### Qwen3-1.7B

더 작은 범용 모델 비교 후보다.
비용은 낮출 수 있지만 이 추출 업무의 한국어 정확도는 검증되지 않았다.
첫 평가 조합에는 넣지 않는다.

## 양자화와 성능

CPU 시험은 GGUF Q4 계열 양자화를 우선 검토한다.
이는 평가 형식 제안일 뿐 성능 보장이 아니다.

처리량과 메모리는 다음 요소에 따라 달라진다.

- CPU 명령어 집합과 메모리 대역폭
- 문서 길이와 문맥 크기
- 추론 도구와 스레드 수
- 양자화 형식
- 출력 JSON 길이

따라서 문서에 초당 토큰 수나 필요 메모리를 고정값으로 두지 않는다.
실제 8~12코어 운영 장비에서 측정한다.

## 평가 자료

한국어 Confluence와 Jira 문서 50~100개를 표본으로 만든다.
가능하면 다음 사례를 포함한다.

- Enum이나 지원 목록이 줄거나 늘어난 문서
- 폐기와 대체 문구
- 새 문서로 이동하는 링크
- 적용 범위와 예외 조건
- 날짜가 없는 문서
- 추출할 신호가 없는 음성 사례
- 표와 목록 안의 값
- 댓글에서만 정정된 값

사람이 원문 근거 구간과 기대 JSON을 확인한다.
모델 이름을 가린 상태로 결과를 비교한다.

## 측정 지표

- JSON 구문 유효률
- 필드별 정확 일치율
- 원문 근거 구간 유효률
- 원문에 없는 값 생성률
- 잘못된 충돌 후보 생성률
- 문서당 지연 시간
- 분당 처리 문서 수
- 최대 상주 메모리

검색 품질 평가에는 다음도 포함한다.

- 기존 검색에서 놓친 실제 충돌을 더 찾는가
- 잘못된 충돌이 답변 품질을 떨어뜨리는가
- 추출 메타데이터가 최종 근거 순위를 개선하는가

## 도입 기준

다음 조건을 모두 충족할 때만 운영 도입을 검토한다.

- 결정적 기준선보다 실제 충돌 재현율이 높다.
- 원문 근거 구간 검증을 통과한다.
- 잘못된 충돌 증가가 허용 범위다.
- 증분 수집 처리 시간을 방해하지 않는다.
- CPU와 메모리가 운영 한도 안에 있다.
- 모델 교체와 재추출 비용을 감당할 수 있다.

이 기준을 통과해도 모델 출력은 보조 정보다.
답변은 원문 문서와 코드 근거를 인용해야 한다.
